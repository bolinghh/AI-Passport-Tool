## 复现

配置 CMake、原生 C 编译器与 Rust 后运行 `python tools/validate.py --host`。
Windows 也可用 C++ Build Tools 运行 `tools/test-host.ps1`。激活 ESP-IDF 5.5.3
后运行 `python tools/validate.py --firmware`。产品不复用根目录忽略的 sdkconfig。
桌面构建使用 Cargo.lock；macOS 需原生测试/构建和带权限声明的 `.app`。

另行运行原始仓库门禁的静态、固件和完整三种模式。没有 Git 元数据的源码包
可用 `python tools/source-gate.py --bash <bash路径>`，它复制到根目录
`build/validation-source-*`，只在副本初始化 Git，并保留结果。Windows 设置
`CC`、`ACTIONLINT_BIN` 为兼容原生工具，先激活 IDF。包装入口使 Git Bash 调用
原生 `python3`/`idf.py`，仅在原生 IDF Python 内移除 MSYS 标识。
原目录保持没有 `.git`；临时元数据只用于验证，不提交、
不配置远程、不发布。

## 故障与数据

当前台式机在短时安全连接通过后出现间歇性发现，RSSI 约 -98 至 -104 dBm。
用户确认没有外置天线。射频条件修正并复测前，持续 GUI 运行仍未验收；
驱动故障码为 0 和访问 Allowed 不能证明无线性能正常。见当前[构建报告](BUILD_REPORT.zh_CN.md)。

Realtek USB 复测解决了本次配置下的发现问题，通过上述短时加密连接和重连
检查。Windows 用 BTHUSB 事件 6 拒绝两个同时启用的无线收发器，应只启用
选中的适配器。运行 `ble-check` 前关闭 GUI，确保只有一个连接来源。
距离和持续音频属于独立验收项目。

没有虚拟输出时开启失败且不采集。录音中停用输出端，检查桌面错误与设备
停止。配对和录音时退出桥接，确认取消和静音。快速开/关/开，确认旧队列数据
不进入新流。长按进入设置关闭麦克风；编辑清单/路由也先关闭再同步。
取消配对会主动删除绑定；固件不擦除 NVS 掩盖初始化错误。合并烧录可能替换
设置，需确认固件和数据影响后批准。软件验证不代表已烧录或安装系统驱动。

## 资源验收

无 PSRAM：LVGL 24 KiB 池和局部绘制缓冲、编码 24 KiB 栈、有界 BLE 队列、
静态 PCM 与常驻编码器，与 NimBLE/BSP/DMA 竞争内部 RAM。检查 ELF/MAP，
安全配对后编码时测量最低堆和最大连续块。真机应稳定在每 60 ms 内完成编码；
如不能，应报告失败，不能将丢音当作端到端成功。虚拟设备回调延迟与独立时钟
需要实际回环/漂移验收。
